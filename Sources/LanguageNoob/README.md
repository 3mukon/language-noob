## Responsibilities

AppKit lifecycle and menus, the transparent WebKit window, validated message bridge and native application composition. `App.swift` composes the window and its lifecycle. `PaperWindow` owns native input routing and retains the active mouse-down event for asynchronous header-drag requests, discarding it on release or drag consumption; `WindowControls` places accessible native minimize and close buttons just above the active paper's right edge. `StudyPage` normalizes resource paths and shares the navigation and message boundary. `AppMenus.swift` owns native menu actions; `StudyController` adapts the shared StudySession to WebKit payloads and owns background library searches. `AppSettings` aliases the shared StudySettings type; invalid preferences recover without blocking offline study.

The native AI settings form accepts local CLI configuration or Messages/Responses API connections. API keys are entered only in a secure native field and saved through StudyAssistant in Keychain; the form never fills a saved value back in. Blank input preserves an existing key, and an explicit checkbox removes it on Save. Switching providers retains unsaved ordinary fields within the dialog and clears unsaved key text. Legacy retired-provider settings recover independently of learning preferences.

The assistant form aligns the actual text origins of native popups and editable/read-only fields, compensating popup decoration and matching label baselines. The provider label uses Claude Code while retaining its existing stored identifier. Labels and controls share their actual AppKit text baseline, including automatic read-only values. A separate enrichment-concurrency popup is editable for every connection mode, defaults to one and allows one to eight; changing providers retains its draft value.

Automatic local selection displays the model, effort and discovered executable as selectable, read-only text. Explicit providers retain editable controls. Each field displays its application override, then a readable local CLI preference, then default. Effort names are shown verbatim (low, medium, high, xhigh, max). The discovered executable is actual editable text, with its full path also in the tooltip. AssistantInheritedText keeps displayed values, edits and saved overrides separate: merely focusing or saving inherited text never pins it, and clearing the model or path restores inheritance. Selecting the effort menu's first item also restores inheritance.

Preference reads run off the UI thread. Before painting a new selection, the native form waits at most 150 milliseconds for one complete model/effort/path snapshot; a fast read never paints intermediate default or loading values. A slower read keeps the same layout and delivers all values together within the native modal run loop. Changing providers, starting a model or path edit, and closing the form invalidate older deliveries. Committing an edit refreshes the dependent preferences, while any field still being edited retains its draft. The execution-path override remains reserved for a specific CLI.

## Not responsible for

Learning rules, SQL persistence and provider protocols belong to the three feature modules. Shared session effects, settings persistence, data locations and dictionary resources belong to StudyRuntime.

## Interface

The menu bar has two flat menus. The application menu groups About and usage help, then learning and AI settings, followed by Quit. The Study menu groups round actions, current-card actions, library search/import and statistics, and language selection. All actions retain their keyboard shortcuts. The selected learning mode and language have native checkmarks. Unavailable end-round and card actions are disabled; AI completion distinguishes queued and active menu titles and rejects duplicate work. Paper headers show concise round, current-language, single-card and assistant result feedback. Replacing a round clears its status and rejects late feedback from that round. Selecting the current language retains the active round without inserting a temporary message. Editing and window actions remain registered as hidden AppKit menu items with enabled key equivalents, preserving native responder routing without extra menu headings.

Library selection opens the selected entry within its query's ordered results. Snapshots retain all round cards but provide a separate ordered `visibleIDs` list and view kind. Only that sequence is painted or interactive; inactive DOM nodes retain drafts and receive their own asynchronous replies. Library navigation wraps from the last result to the first and from the first to the last with the same directional paper motion as neighboring results. A single result stays in place; browsing never grades or finishes study. The paper's return-to-study action restores the saved learning selection, draft and replies. Adding a word still uses the study round's pending-assessment reuse rules. Repeated searches reuse browse identities until the round ends.

Library queries run through the storage module's background search actor. Input retains its 120 ms debounce, waits for IME composition to finish and invalidates the previous request immediately. Each result carries a request identity as well as its query and round. Pending results are inert; closing the library cancels pending work, and obsolete results and errors cannot modify the current view. Each result presents its word, optional pronunciation and part of speech beside its definition. Missing metadata is omitted, and all vocabulary values remain plain text. The controller retains the displayed result snapshot so opening a word does not repeat the query. Imports and enrichment updates invalidate that snapshot and refresh an active query. Round replacement, language changes and termination cancel search alongside other temporary work.

Language selection preserves an open library panel, its query, focus and text selection. The title continuously identifies the selected language, old-language rows are removed, and a new request uses the replacement round's identity. No learning entrance animation or transient new-round message interrupts this view. Explicit round-start actions still return to the study papers. The library header and its title share native window dragging; close controls, inputs, results and modified/secondary clicks retain their own interactions. Library visibility pauses automatic word preparation; closing the panel or choosing a result restores the appropriate current paper.

StudySession supplies per-word automatic preparation state. Queued and active cards show distinct quiet header labels, with specific placeholders when a definition is missing. Successful completion updates the retained paper after persistence, using the existing motion deferral. Failures preserve source content and expose a retry hint without a modal error or automatic retry loop. Hidden questions retain their reveal boundary, and a displayed prompt never changes direction. Cached entries offer a regeneration action with a native confirmation dialog; cancellation makes no request, and confirmation is bound to the same round and word. Ordinary completion reuses saved results. Successful regeneration reports completion after saving and preserves the old result on failure.

`StudyWebView` filters WebKit's Reload item from the native contextual menu using its item identifier. Native text selection, copy, paste and other editing menu actions remain available; the page does not suppress contextual menus globally.

Starting a new round from the summary action or native learning-mode menu turns the captured, inert current paper into the actual first word paper. `paper-round.js` reuses the contained answer-turn trajectory, then spreads the rear papers in at most two shared groups; covered cards remain opaque within their group instead of becoming separate animated layers. The follow-up note enters during the later spread only when the first card is already revealed. The entry timeline lasts 1.84 seconds, with the note starting at 1.48 seconds. Native hit geometry follows the exposed moving faces. Repeated activation is locked until the round response or an explicit failure, navigation waits for settlement, and replacement, library opening, resize and reduced motion discard or settle the same owned effects. Empty workloads turn the captured current face into their real summary through the same lifted-paper trajectory. One-card rounds do not invent a rear stack, and ordinary startup remains immediate.

Vocabulary import is available from the native Study menu and uses an independent application-modal file panel. Attaching a sheet would dim the full rectangular study window, including transparent space over other applications. Cancellation retains the current view and round, and the panel closes before import results or validation errors appear. The library paper contains only its heading and a close action aligned on the text baseline; it does not repeat the import action. While this search paper is open, native minimize and close controls are hidden and excluded from pointer routing. Closing the paper or choosing a result restores their usual pointer-activity behavior.

The executable bundles its paper `Resources` and uses StudyRuntime’s shared BundledVocabulary resources. Dictionary installation and conservative sample migration preserve existing user records through StudyStorage. Missing meanings are explicitly labeled; unrevealed entries without a meaning offer a reading-recall prompt before displaying their pronunciation. The data preparation tool consumes local upstream files and never runs during application startup. The web view accepts a fixed `BridgeMessage.Operation` enum. State-changing commands and replies carry a round ID; old commands cannot mutate a replacement round. Successful writes are acknowledged through card snapshots. Introduction papers have no action footer and do not persist progress; learners navigate to the subsequent recall papers to assess themselves. Graded papers show a confirmation without an additional navigation button; successful grading still advances automatically, and returning to a graded paper retains ordinary stack navigation. Library practice appends to the active round or reuses unfinished assessments. Snapshots expose the core-selected first pending assessment. Manual study navigation wraps from first to last and last to first, independently of assessment state, with the same continuous directional motion as library browsing. A single paper stays in place with visible feedback. Only advancement after an acknowledged grade seeks the first pending assessment at the tail, or completes a fully graded round. Explicit ending reports the number left unfinished. Summaries count recorded grades, not reading or navigation. Startup immediately opens the selected workload; the summary paper is not a welcome screen. Completed, unfinished and empty workloads have distinct copy in a left-aligned paper header, body and footer. Zero-count statements are omitted, and saved-progress and temporary-message notices sit separately beneath the next-round action. The AI menu names definitions and examples; its tooltip also names pronunciation and part of speech. Missing entries can be completed or retried, and already-saved entries require confirmation before regeneration through the shared queue.

`paper.js` retains card DOM nodes and drafts while reconciling snapshots. It serializes navigation and defers snapshots during motion. Transform and opacity animations use a gentle shared timeline; only picked-up papers exchange layers, through a separate discrete effect, and unchanged text and opacity are left alone. Ordinary navigation picks up one paper. A forward return from the tail carries any intervening papers together and places them beneath the destination without changing their relative order. Gesture direction is explicit, so wrapping to a lower index remains a forward motion. Queued input can continue across that boundary. The shared deck layer is prepared while idle (L-0003). `paper-motion.js` contains pure trajectory, layer and projected-boundary calculations used by both the renderer and tests. Navigation and dragging keep paper and visible-note surfaces inside the window (L-0002). Both drag directions share the same soft travel limit; releasing a sufficient backward pull from the first study card wraps to the last card. The attached note tucks inward near the window edge so its overhang does not stop the word paper prematurely. Reverse navigation carries the current paper outward before settling it behind the previous paper; its visible excursion follows the available forward range rather than its short final offset. Release and cancellation retain the actual paper, note and shadow poses. At layer exchange, the deck yields as a group so the turning paper retains a visible face instead of becoming a slit (L-0005).

Unrevealed assessments hide the follow-up note from layout, focus and native hit geometry, and both the renderer and controller reject premature questions. The reveal action sits at the paper's center; paper actions use underlined text without filled button chrome, retaining semantic buttons and keyboard focus. `paper-reveal.js` lifts a temporary inert prompt face away from the stack, carries it through a tilted turn, and lands the live answer paper before the follow-up note becomes prominent. The paper keeps its 1.12-second motion; the note starts a 320-millisecond fade at 1.04 seconds, and the settled paper holds while that fade completes. The contact shadow fades completely as the paper lifts, leaving only a filled, softly blurred moving footprint until landing restores contact (L-0001). The footprint has no hollow rectangular edge, and its blur stays constant while only transform and opacity animate. The narrow underside moves with the paper through the edge crossing; no stationary full-size backing remains. Projected corners constrain the entire motion to the viewport, including enlarged reading. Only the current paper participates. The live paper, editor and reading scale remain intact. A pending action retains focus ownership even when disabling its button makes WebKit drop focus, and navigation moves focus off a paper before making it inert. Navigation waits for settlement; replacement discards the effect, and library opening, reading restoration or reduced motion settles it safely. Temporary painted faces participate in native surface geometry and are removed with their animations. WebKit checks cover visible pickup, hidden-note geometry, interaction locks and lifecycle interruptions; rendered comparisons enforce identical pickup and settlement frames and the absence of a stationary contact shadow at three intermediate poses, at ordinary and enlarged sizes. Image fixtures provide new card values and require an active turn before sampling, so a static no-op cannot pass as an animation.

`paper-reader.js` owns reading zoom and focus restoration, retaining one text layout scale through opening, settlement and closing (L-0004). Paper movement, background fades and note text share an eased timeline; the word paper's existing shadow travels with it. Background papers stay opaque inside the existing deck, which fades as one surface, preserving occlusion without promoting every covered sheet (L-0003). Only the active card moves into a foreground host; the same editor, draft, selection and scroll positions are retained, and the card returns to its logical order on close. Restoring during opening starts from the currently painted properties and shortens the return according to the distance travelled. Reading keeps its focus and interaction boundary until restoration finishes. Reduced motion skips the transition; resizing or replacing a round cancels every reading effect and restores the original inline styles.

Text and paper have separate gesture regions (L-0006). Vocabulary and reply content uses inline `ln-selectable` spans so native hit testing follows each rendered text line; block width, flex gaps, separator padding and short-line trailing space remain paper regions. Content updates retain these spans. Text uses the native cursor, double-click selection and drag selection; inputs retain native editing and select-all. Blank word paper supports horizontal dragging, and blank areas on either paper support double-click reading zoom. The header remains a window-movement region. The same exclusion predicate protects selection from both paper gestures before pointer capture, retaining text ownership when a selection crosses blank space or another line. Modified gestures and arrows, and arrows while text is selected, remain native; ordinary arrows without a selection navigate the stack. Keyboard focus still exposes the accessible reading controls, and Escape restores the paper. The native select-all shortcut routes to the page only when its WebKit view owns focus: the focused editor selects its value, otherwise the active paper selects its visible content. The last pointer region distinguishes the word paper from its conversation; reading uses the enlarged paper. Library search/results have their own boundary, and native dialogs retain the standard responder action. Covered papers, hidden answers and unrelated drafts cannot enter document select-all.

Native window controls start hidden, appear on pointer motion over the papers or their control region and fade after inactivity. Hover and keyboard focus keep them visible; hidden controls do not intercept clicks. The presentation reports the control anchor on layout or reading changes, and AppKit clamps it to the window without polling or per-frame anchor messages. Controls remain reachable during navigation and reading zoom. Minimize (Command-M) retains the active round, drafts and reading position; show (Command-0) restores the window from the Dock. Close (Command-W) follows the window lifecycle: it ends the round and clears temporary conversations while preserving saved learning progress. Hover tooltips and the application menu’s usage help explain that distinction.

Transparent space outside the visible paper outlines passes mouse input to the underlying application (L-0007). `paper-surfaces.js` measures four zero-size corner markers through WebKit's actual transforms and perspective, preserving tilted corners instead of reserving their rectangular envelopes. Markers are prepared with each card; only the few exposed surfaces are measured during motion. Geometry messages are deduplicated and stop while idle. Completion and library surfaces replace the deck's regions. `PaperWindow` validates these viewport coordinates and combines them with revealed native controls before changing `ignoresMouseEvents`. Local and global mouse monitors support leaving and re-entering the papers without intercepting other applications' events. A held-button gesture keeps its existing routing until release. Moving and resizing the window updates routing, unavailable windows stop monitoring, and renderer termination clears stale geometry.

## Dependencies

The application icon source is `Resources/AppIcon.png`. `tools/build-app.sh` uses the system `sips` and `iconutil` tools to generate standard and Retina representations from 16 through 1024 pixels, preserving the full artwork. The resulting `AppIcon.icns` is bundled in the application resources and referenced by `CFBundleIconFile`.

StudyRuntime, StudyCore, StudyStorage, StudyAssistant, AppKit, WebKit and UniformTypeIdentifiers. Other production modules must not import this executable. The standalone application-test harness compiles the controller, settings and page boundary with its native fixtures. Pixel, interaction and reading/round-entrance suites run on three independent, partially visible floating windows so WebKit continues delivering animation frames while all suites share the existing process watchdog.

## Invariants

The web view has a nonpersistent data store, a restrictive content policy and file-only navigation. Only bundled resources load; imported and assistant text uses `textContent`. UI copy is Simplified Chinese. Papers remain opaque and painted during navigation, including covered sheets; layer exchange happens only after clearing the stack. Ambient shadows, lift shadows and notes have independent continuous opacity, and reverse pickup uses a layer strictly below the stationary deck (L-0001). The attached note fades during pickup and returns after the deck's lateral movement settles. Reading uses 2D transforms without switching to CSS zoom or replacing input nodes; opaque background papers continue to cover underlying text within the faded group. Settings contain no credentials.
